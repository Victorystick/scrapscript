scrap-web playground

Build a little website with scraps, in the Elm architecture. main.scrap is the app: the model to start with, init, the update of the model with each message that the site sends, and the view of the model that the site shows. It runs in scrap-web.wasm, which the server builds from the source each time the page loads, so a reload runs what you edited, of the host or the page.

Each editor holds a draft, which refers to others by path, as $"./html.scrap". The page keeps the messages that the site sends, and replays them when you edit a draft, as Elm's debugger does: edit update, and the model that they lead to changes with it. Once the updates settle, state.scrap shows the model, as a scrap: edit it, and the site starts from it. The address bar keeps every draft, to share.

        The type of an app
        
    An app has the type app model msg, for a model and messages of its choosing. A view is text, or an element with attributes, handlers of events that send a message, or a function of the value of the event's target that makes one, as an input's, and children. An element's key attribute matches it with its siblings from one view to the next, rather than their order.
    

    -- The web platform's contract: an app in the Elm architecture.
--
-- An app keeps its own model, of type model, which the host never inspects.
-- The host shows the page that `view` makes of the model, starting with
-- `init`, and passes `update` each message that the page sends, with the
-- model, for the next one.

app

; app   : type -> type -> type = model => msg => { init : model, update : msg -> model -> model, view : model -> html msg }
; html  : type -> type = msg => [#text text, #el { tag : text, attrs : list (attr msg), children : list (html msg) }]
; attr  : type -> type = msg => [#attr { name : text, value : text }, #on { event : text, msg : msg }, #on-value { event : text, msg : text -> msg }]
